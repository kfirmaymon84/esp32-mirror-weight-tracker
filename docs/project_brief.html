Hardware / BLE Reverse-Engineering

Xiaomi S200 Scale → ESP32

Reading live body-weight off a Xiaomi Smart Scale S200 over Bluetooth. The protocol is fully cracked and working on PC; next stop is a standalone ESP32 with a display.

Protocol solved Working PC reader + live GUI Next: ESP32 port

What this is

The S200 keeps weight off its BLE broadcast entirely — the advertisement is just an idle beacon. The number is delivered only over an authenticated, encrypted GATT session (Xiaomi's MIoT / “mible” protocol). We captured the phone app talking to the scale, reverse-engineered the handshake and data format, and now read live weight from a plain PC. The end goal is an ESP32 that does the same on its own and shows the weight on a screen.

How we got here

  1. ✓Caught the broadcast
    Found the scale over BLE and decoded its MiBeacon frame — confirmed weight is not broadcast.
  2. ✓Pulled the bind key + token
    Extracted per-device secrets from the Mi cloud account with the Xiaomi token extractor.
  3. ✓Sniffed the Mi Home app
    Android HCI snoop log via adb bugreport, decoded the GATT traffic → mapped the full auth + data protocol.
  4. ✓Working PC reader
    Authenticates, derives session keys, decrypts the weight stream. Verified against a real 104.20 kg weigh-in.
  5. ✓Live desktop app
    A window that shows the number in real time — blue while settling, green when it locks.
  6. →ESP32 + display (in design)
    Re-implement the reader on-device and drive a screen. Architecture being decided.

How weight is read

A GATT client connects, runs the Mi handshake, then decrypts a small streamed record. The core:

# session-key derivation (token-based)
salt    = random_key(16) + remote_key(16)
derived = HKDF-SHA256(mi_token, salt, "mible-login-info", 64)
dev_key, app_key = derived[0:16], derived[16:32]
dev_iv,  app_iv  = derived[32:36], derived[36:40]

# verify device, then send our proof
server_proof == HMAC-SHA256(dev_key, remote_key + random_key)
client_info  =  HMAC-SHA256(app_key, random_key + remote_key)

# data channel: AES-CCM, tag=4
nonce = iv(4) + 0x00*4 + seq(4, LE)

# weight frames (decrypted)
0x19  intermediate  → uint16 LE @ off 23, / 100 = kg
0x22  stable/final  → CSV after 0xA0: id,user,weight_10g,imped,ts

Transport runs over four 0xFE95 characteristics — an auth channel, an encrypted send channel, an encrypted receive channel, and a device-info channel — with a small framed reliable-transfer layer (ready / ok / ack).

Next: ESP32 architecture

Porting the reader on-device. Open decisions to settle before building:

  • Board — ESP32 / S3 / C3? (S3 has the most headroom for a display + LVGL.)
  • Display — type, size, driver (e.g. ILI9341 TFT, SSD1306 OLED, e-paper).
  • Output — screen only, or also push out over Wi-Fi (MQTT / HTTP / Home Assistant)?
  • Framework — Arduino or ESP-IDF. Either way the port needs NimBLE (BLE client) + mbedTLS (HKDF-SHA256, HMAC-SHA256, AES-CCM).
Note: the scale accepts one BLE connection at a time. When the ESP32 is connected, keep the phone's Mi Home app closed/away, and vice-versa.
